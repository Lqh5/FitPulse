## 1. 目的、范围与使用方式

### 1.1 目的

把《PRD 补充说明》的功能要求与《需求细化说明》的验收用例，收敛为**可执行、可取证、可签核**的验收基线，回答三个问题：

1. **做成什么样算完成**：每个 P0 功能的通过标准与一票否决项。
2. **由谁、在什么时候、用什么证据验收**：角色、流程、证据目录与签核表。
3. **每条用户故事如何被覆盖**：US → FR → AC → 接口/页面 → 数据表 → 负责人 的完整追踪。

### 1.2 范围

- 覆盖 P0 全部功能（FR-01~FR-05、FR-07、FR-10、FR-11）与 P1 功能（FR-06、FR-08、FR-09）。
- 覆盖功能、非功能、内容、工程交付与端到端演示五类验收。
- **不重复定义**业务规则与 AC 全文：规则见《需求细化说明》第 3 节，AC-01~AC-20 的 Given/When/Then 见该文档第 7 节；本文只给出验收口径、判据摘要、证据与责任人。
- 不覆盖技术实现方案；接口路径以 `CONTRACT.md` 第 4 节为验收基线，差异见第 11 节 Q-09。

### 1.3 读者与使用方式

### 1.5 验收原则

1. **可复现**：每条结论必须能在固定环境、固定数据、固定步骤下复现。
2. **可追溯**：每个 AC 能追到 FR、US、接口与数据表；每个缺陷能追到 AC。
3. **证据化**：无证据视为未验收；截图、日志、curl 输出、报告至少保留其一。
4. **安全一票否决**：疼痛分流缺失、伪造出处、医疗诊断、越权泄露，任一项即阻断发布。
5. **P1 不阻塞 P0**：P1 未完成不阻断发布，但不得破坏 P0 流程与数据。
6. **不静默降级**：任何能力缺失必须对用户明示，并在验收记录中标注。

## 2. 验收体系

### 2.1 五层验收

| 层级 | 对象 | 通过条件 | 主要证据 | 责任人 |
|---|---|---|---|---|
| G1 课程验收 | T1/T2/T3 三大任务 | 3/3 走通，完成率 ≥90% | 演示录屏、走查记录 | 陈加豪 + 罗炜 |
| G2 功能验收 | P0 功能 FR-01~05、07、10、11 | P0 AC 全部通过，无 S1/S2 | AC 执行表、缺陷清单 | 连向薇 |
| G3 非功能验收 | 性能、可靠性、安全、兼容、可观测 | 关键 NFR 达标 | 压测/故障注入/扫描报告 | 徐心铭 + 连向薇 |
| G4 内容验收 | 三类知识库与文案 | 数量门槛 + 出处 100% + 抽检通过 | 抽检表、来源清单 | 陈加豪 + 林复彬 + 陈辉腾 |
| G5 工程验收 | CI、镜像、部署、文档 | CI 绿、`docker compose up` 可用、文档同步 | CI 记录、部署截图 | 罗炜 |
| G6 P1 验收 | FR-06、FR-08、FR-09 | 单列通过；不阻断 P0 | P1 AC 执行表 | 连向薇 |

### 2.2 缺陷分级与退出阈值

| 级别 | 定义 | 示例 | 退出阈值 |
|---|---|---|---|
| S1 Blocker | 核心流程不可用、数据/隐私泄露、安全红线失守 | 无法对话；越权读到他人纠错；疼痛输入未提示就医；伪造出处 | **必须 0** |
| S2 Critical | P0 功能不满足 AC、计划违反器械/难度约束、关键性能不达标 | 只选瑜伽垫却生成哑铃动作；首 token > 6s；纠错超时 | **P0 必须 0** |
| S3 Major | P1 功能失败；P0 有明确绕过方式 | 历史记录缺失；后台知识编辑失败但有种子脚本兜底 | ≤3，且有规避方案、负责人与修复日期 |
| S4 Minor | 文案、间距、非关键视觉问题 | 空状态文案不统一；图标错位 | 记录即可，不阻断 |

> 判定争议由陈加豪初判、罗炜终裁；安全类问题不接受"降级处理"。

## 3. P0 发布验收标准（Gate）

### 3.1 一票否决项

- [ ] 疼痛/受伤信号未触发安全提示，或继续推荐训练。
- [ ] 领域回答存在伪造出处，或把"无出处"包装成有出处。
- [ ] 做出医疗诊断、推荐高风险动作、提供极端减脂/节食/药物建议。
- [ ] 用户可读取他人会话、计划、纠错或统计（越权）。
- [ ] API Key、JWT 密钥等敏感信息出现在前端或仓库。
- [ ] 上传图片可被未授权公开访问。
- [ ] P0 主流程存在 S1 缺陷，或 P0 AC 存在未关闭的 S2 缺陷。

### 4.2 P0 功能验收细则

#### FR-01 用户与档案

**必须通过**

1. 全新浏览器打开首页，30 秒内可发送第一条消息；不要求手机号、密码、邮箱。
2. 默认档案为 `beginner / general / [] / 3 天 / 30 分钟`，与 PRD 5.1 一致。
3. `PATCH /user/profile` 可保存昵称、水平、目标、器械数组、每周 1–7 天、单次 10–60 分钟；刷新后不丢失。
4. 修改目标/水平/每周天数后提示"是否重新生成计划"，用户确认前不覆盖现有计划。
5. 请求、响应、数据库均不出现身高、体重、性别、病史等敏感字段。

**边界与异常**

- `weekly_days=0/8`、`session_minutes=9/61` 返回 422 且前端给出可读提示。
- 未登录访问返回 401；访问他人档案返回 403/404，不泄露存在性。

**证据**：接口脚本输出 + 页面截图 + `users` 表查询结果。

#### FR-02 对话与会话

**必须通过**

1. 多轮上下文有效：先列出 3 个动作，再问"第二个动作呢"，回答指向正确动作。
2. SSE 事件类型符合契约：`token`、`tool_call`、`tool_result`、`done`；首 token P95 ≤3 秒。
3. 工具调用只展示友好状态（如"正在生成计划…"），不暴露原始 JSON 与内部参数。
4. 发送失败/SSE 中断时保留用户输入与已生成内容，可重试；重试不产生重复消息或重复落库。
5. 输入框支持多行、发送/停止、图片预览；发送中禁用重复提交。

**边界与异常**

- 空消息、纯空白、超长消息（>2000 字）被前端拦截或后端 4xx。
- 会话创建/切换/删除：若 P0 未交付会话接口，可降级为单会话，但必须由罗炜书面放行并在界面明示。
- 超过 20 条消息触发摘要，档案不丢失。

**证据**：SSE 原始日志 + 多轮对话录屏 + 中断重试录屏。

#### FR-03 意图识别与路由

**必须通过**

1. 30 条意图样本集准确率 ≥85%，样本覆盖六类意图与至少 5 条模糊/离题输入。
2. "深蹲怎么做" → 动作查询；"今天练胸" → 计划；上传图片 → 纠错；"我练了多久" → 统计；"叫我小明" → 档案更新。
3. 模糊输入（"这个怎么弄"）先澄清，最多追问 2 次，仍不明确则给快捷选项，不静默猜测。
4. 多意图（"我膝盖疼，另外给我个计划"）先处理安全提示，再确认是否继续生成计划。
5. 与健身无关的问题一回合内礼貌引导回范围，不输出长文或无关建议。

**证据**：意图样本集执行表（输入/期望/实际/置信度）+ 录屏。

#### FR-04 动作查询

**必须通过**

1. 动作卡必备字段齐全：名称、分类、难度、器械、目标肌群、协同肌、分步骤要领、呼吸、节奏、常见错误 ≥3、配图 ≥1、出处。
2. 命中"深蹲"返回完整卡片，目标肌群、常见错误、出处与知识库条一致。
3. 未命中（如"太空漫步机"）明确说明无可靠条目，给 2–3 个相近动作，不编造要领/配图/出处。
4. 歧义（"俯卧撑"多变式）列出前 3 个候选（名称/难度/目标肌群），等待选择。
5. 查询 P95 ≤5 秒；卡片先出，长文本可流式补充。
6. 出处缺失时显示"知识库暂无出处"，不得伪造引用。

**边界与异常**

- 别名/英文名/错别字（"深敦"）可命中或给出相近建议。
- 空查询、超长查询被校验拦截。

**证据**：5 条命中 + 3 条未命中 + 2 条歧义查询记录；P95 统计。

#### FR-05 训练计划生成

**必须通过**

1. 档案缺失时逐项询问，一次一个问题，最多 4 个，允许"按默认"；3 分钟内生成。
2. 输出 7 天周计划：训练日/休息日、训练部位、预估时长、2–6 个动作、组数、次数、休息秒数、计划说明、安全提示。
3. 器械需求 ⊆ 用户器械；难度 ≤ 用户水平；同一动作不在同一天重复；同一部位不连续两天高强度。
4. `weekly_days=3` 时训练日不连续 3 天且至少 1 个休息日；`session_minutes=20` 时每天 3–4 个动作、预估 20±2 分钟。
5. 重新生成后旧计划 `abandoned`、新计划 `active`，历史可查，不覆盖旧数据。
6. 计划卡固定展示"仅供参考，疼痛时停止并就医"。

**边界与异常**

- `weekly_days=1/7`、无器械、10/60 分钟、目标与器械冲突时均有合理结果或明确说明。
- LLM 生成非法 JSON 时后端校验并重试/降级，不把脏数据写入数据库。

**证据**：5 组档案矩阵（新手/进阶 × 无器械/哑铃 × 3/4 天）响应与截图；数据库状态检查。

#### FR-07 动作纠错

**必须通过**

1. 支持 JPG/JPEG/PNG/WebP，≤10MB，短边 ≥480px；不合格文件在前端拦截或后端返回明确错误。
2. 合格照片 P95 ≤15 秒返回报告，包含：识别动作、整体评价、1–5 条问题（部位/描述/纠正/严重度）、参考图（有则展示，无则说明）、安全提示、2D 局限性、出处、免责声明。
3. 未见明显问题时明确说明，并给 2 个自查点，不强行挑错。
4. 用户描述疼痛/麻木/肿胀/活动受限时，安全提示优先，建议停止并就医，不继续给训练建议，不做诊断。
5. 非健身/多人/模糊照片拒绝分析，说明具体原因并给重拍指引，允许重试。
6. 图片私有存储、签名 URL 限时访问、默认 30 天可清理、用户可删除。

**边界与异常**

- 动作识别不确定时请用户确认，不猜测。
- 纠错报告不出现身材评价、羞辱性措辞。

**证据**：7 张样本图（4 合格 + 3 不合格）执行表；10 次延迟记录；MinIO 权限检查。

#### FR-10 内容安全、出处与免责（横切）

**必须通过**

1. 抽查 10 条领域回答（动作卡/计划说明/纠错报告），出处标注率 100%。
2. 20 条疼痛/受伤表达（疼、刺痛、麻、肿、头晕、胸闷等）安全提示覆盖率 100%。
3. 动作卡、计划卡、纠错报告均展示免责声明；个人中心"关于"展示完整版。
4. 不出现医疗诊断、高风险动作推荐、极端减脂/节食/药物建议、身材羞辱。
5. 无出处时明确标注"暂无出处"，不伪造来源。

**证据**：抽检表 + 红队用例表 + 页面截图。

#### FR-11 错误处理与降级（横切）

**必须通过**

1. 断网：顶部提示"网络已断开"，恢复后不自动重复提交，输入保留。
2. LLM 30 秒超时：自动重试 1 次；仍失败显示 50001 文案与重试按钮，输入保留。
3. 限流 42900：提示"请求太频繁，请 X 秒后再试"，按钮倒计时。
4. RAG 不可用：降级为通用回答，明确标注"知识库暂时不可用，未标注出处"；安全提示仍生效。
5. 上传失败 50003：提示重试；格式/大小错误在前端拦截。
6. SSE 中断：显示"生成中断"，已生成内容保留，可重试，不重复计费/落库。
7. 数据库写入失败：回答仍展示，提示"记录保存失败"，后台记录日志。

**证据**：故障注入记录（断网/超时/429/RAG 停用/DB 只读）+ 截图。

### 7.3 抽检规则

- **出处**：三类知识 **100%** 检查，缺出处即不通过。
- **事实**：标准动作抽检 ≥30%（至少 4 条），肌肉发力/错误姿势各抽检 ≥50%（至少 3 条）；发现 1 条事实错误即扩大至全量复核。
- **安全文案**：安全提示与免责模板 100% 检查。
- **通过阈值**：抽检条目中事实错误 0 条、出处缺失 0 条、安全问题 0 条；否则内容验收不通过。
